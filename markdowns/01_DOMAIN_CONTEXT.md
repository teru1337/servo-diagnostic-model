# 01_DOMAIN_CONTEXT.md

# Предметная область: диагностика сервопривода по телеметрии

## 1. Назначение документа

Этот документ объясняет предметную область проекта.

Coding agent должен понимать, что задача не является абстрактной обработкой CSV-файла. Нужно реализовать диагностическую модель для промышленного сервопривода.

Модель должна учитывать инженерный смысл параметров:

- скорость;
- ток;
- момент;
- напряжение DC-шины;
- температура;
- состояние CiA 402;
- коды ошибок;
- режим работы;
- паспортные ограничения.

Главная цель — превратить сырую телеметрию в понятное диагностическое заключение.

---

## 2. Что такое сервопривод в рамках проекта

Сервопривод — это электромеханическая система управления движением.

В упрощённом виде он включает:

1. Сервопреобразователь.
2. Серводвигатель.
3. Энкодер.
4. Контур управления.
5. Силовую часть.
6. Коммуникационный интерфейс.
7. Механическую нагрузку.

Сервопривод может работать в разных режимах:

- управление положением;
- управление скоростью;
- управление моментом;
- комбинированные режимы;
- режим удержания позиции;
- режим разгона;
- режим торможения;
- режим равномерного движения.

В проекте не нужно реализовывать управление приводом. Нужно анализировать телеметрию, которую привод или эмулятор уже передал в систему.

---

## 3. Почему диагностика сервопривода важна

Сервоприводы используются в:

- автоматизированных производственных линиях;
- станках;
- робототехнических системах;
- испытательных стендах;
- системах позиционирования;
- механизмах с высокой точностью движения.

Отказ сервопривода может привести к:

- останову оборудования;
- перегреву;
- потере точности;
- аварийному отключению;
- повреждению механики;
- простою производственной линии;
- затратам на ремонт.

Поэтому оператору и инженеру важно видеть не только текущие числа, но и их инженерную интерпретацию.

---

## 4. Почему обычных порогов недостаточно

Простой пороговый мониторинг отвечает только на вопрос:

> Превысил ли параметр установленный предел?

Например:

- температура выше 80 °C?
- ток выше номинального?
- напряжение ниже допустимого?
- есть ли ошибка?

Но такой подход не отвечает на более важные вопросы:

- параметр пока нормальный, но быстро ухудшается?
- текущее значение нормально для движения, но ненормально для удержания?
- ток не превышает номинал, но стал в несколько раз выше обычного?
- температура ещё безопасная, но имеет опасный тренд?
- DC-шина в допустимом диапазоне, но стала нестабильной?
- момент и ток перестали соответствовать друг другу?

Именно поэтому нужна физико-статистическая диагностическая модель.

---

## 5. Основные диагностические параметры

### 5.1. Скорость

Поле:

```text
velocity
```

Единица:

```text
RPM
```

Скорость показывает, как быстро вращается двигатель.

Использование в диагностике:

- определение фаз движения;
- поиск превышения допустимой скорости;
- анализ разгона и торможения;
- поиск микроколебаний;
- связь со значениями тока и момента.

Примеры диагностических ситуаций:

| Ситуация                                 | Возможная интерпретация                          |
| ---------------------------------------- | ------------------------------------------------ |
| Скорость высокая, ток умеренный          | Нормальное движение                              |
| Скорость низкая, ток высокий             | Возможная механическая нагрузка или заклинивание |
| Скорость резко скачет                    | Возможны колебания, ошибка управления или шум    |
| Скорость равна нулю, момент присутствует | Удержание позиции или нагрузка на вал            |

---

### 5.2. Ток

Поля:

```text
current
current_A
```

Единицы:

- `current` может быть в промилле или относительной величине;
- `current_A` — ток в амперах.

Ток является одним из ключевых диагностических параметров.

Использование в диагностике:

- оценка электрической нагрузки;
- оценка тепловой нагрузки;
- выявление перегрузки;
- поиск заклинивания;
- анализ нагрузки в режимах разгона и удержания.

Особенно важен RMS-ток.

RMS-ток показывает эффективную нагрузку за окно времени.

Формула:

```text
current_rms = sqrt(mean(current_A^2))
```

Примеры диагностических ситуаций:

| Ситуация                         | Возможная интерпретация                     |
| -------------------------------- | ------------------------------------------- |
| RMS-ток низкий                   | Низкая нагрузка                             |
| RMS-ток высокий                  | Повышенная тепловая нагрузка                |
| Пиковый ток высокий              | Кратковременная перегрузка                  |
| Ток высокий при малой скорости   | Возможная механическая проблема             |
| Ток растёт при одинаковом режиме | Возможная деградация или изменение нагрузки |

---

### 5.3. Момент

Поля:

```text
torque
torque_Nm
```

Единицы:

- `torque` может быть в промилле или относительной величине;
- `torque_Nm` — момент в Н·м.

Момент показывает механическую нагрузку на валу.

Использование в диагностике:

- оценка нагрузки;
- сравнение с номинальным и максимальным моментом;
- поиск перегрузки;
- анализ удержания;
- анализ механического сопротивления.

Примеры диагностических ситуаций:

| Ситуация                     | Возможная интерпретация                                                      |
| ---------------------------- | ---------------------------------------------------------------------------- |
| Момент низкий                | Нагрузка мала                                                                |
| Момент высокий при разгоне   | Может быть нормой, если профиль движения резкий                              |
| Момент высокий при удержании | Возможна внешняя нагрузка                                                    |
| Момент растёт вместе с током | Нагрузка действительно увеличилась                                           |
| Ток растёт, момент не растёт | Возможна неэффективность, шум, измерительная проблема или некорректный режим |

---

### 5.4. Напряжение DC-шины

Поле:

```text
dc_bus_voltage
```

Единица:

```text
V
```

DC-шина — промежуточная шина постоянного напряжения внутри сервопривода.

Использование в диагностике:

- поиск просадки питания;
- поиск перенапряжения;
- оценка стабильности питания;
- анализ торможения и рекуперации;
- диагностика OV/UV-состояний.

Примеры диагностических ситуаций:

| Ситуация                            | Возможная интерпретация                              |
| ----------------------------------- | ---------------------------------------------------- |
| DC-шина стабильна                   | Питание в норме                                      |
| DC-шина проседает                   | Возможна проблема питания                            |
| DC-шина резко растёт                | Возможна рекуперация или проблема тормозного контура |
| Высокая дисперсия DC-шины           | Нестабильное питание или шум                         |
| DC-шина близка к аварийному пределу | Риск отключения привода                              |

---

### 5.5. Температура

Поле:

```text
drive_temp
```

Единица:

```text
°C
```

Температура показывает тепловое состояние силовой части привода.

Использование в диагностике:

- выявление перегрева;
- оценка теплового тренда;
- косвенная оценка нагрузки;
- предупреждение предаварийного режима.

Для температуры важно учитывать не только абсолютное значение, но и скорость изменения.

Пример:

```text
temp_slope = изменение температуры за секунду
```

Примеры диагностических ситуаций:

| Ситуация                              | Возможная интерпретация                  |
| ------------------------------------- | ---------------------------------------- |
| Температура стабильна                 | Нормальный режим                         |
| Температура высокая                   | Риск перегрева                           |
| Температура быстро растёт             | Ранний признак тепловой проблемы         |
| Температура растёт вместе с RMS-током | Нагрузка вызывает нагрев                 |
| Температура растёт при низком токе    | Возможна проблема охлаждения или датчика |

---

### 5.6. Statusword

Поле:

```text
statusword
```

`statusword` — слово состояния привода. Оно содержит набор битов, по которым можно определить состояние сервопривода.

Для MVP не обязательно реализовывать полный стандарт CiA 402 идеально. Но нужно предусмотреть декодирование ключевых состояний.

Минимально важные состояния:

- привод готов;
- привод включён;
- работа разрешена;
- предупреждение;
- авария;
- ошибка;
- управление активно.

В коде нужно сделать отдельный модуль для декодирования `statusword`, чтобы позже можно было уточнить битовые маски.

Пример подхода:

```python
def decode_statusword(statusword: int) -> dict:
    return {
        "ready_to_switch_on": bool(statusword & 0x0001),
        "switched_on": bool(statusword & 0x0002),
        "operation_enabled": bool(statusword & 0x0004),
        "fault": bool(statusword & 0x0008),
        "voltage_enabled": bool(statusword & 0x0010),
        "warning": bool(statusword & 0x0080)
    }
```

Если в будущем будут уточнены биты для конкретного привода, нужно будет заменить конфигурацию, а не переписывать всю модель.

---

### 5.7. Error code

Поле:

```text
error_code
```

Код ошибки показывает наличие конкретной неисправности или аварийного события.

Базовое правило первой версии:

```text
если error_code != 0, состояние должно быть critical
```

Даже если все остальные параметры нормальные, наличие ошибки должно доминировать в классификации.

Позже можно будет добавить таблицу расшифровки кодов ошибок:

```json
{
  "0": "No error",
  "1001": "Overvoltage",
  "1002": "Undervoltage",
  "2001": "Overtemperature"
}
```

Но в первой версии достаточно:

- обнаружить ненулевой код;
- повысить риск ошибки;
- сформировать рекомендацию обратиться к таблице ошибок;
- классифицировать состояние как критическое или предупреждающее.

---

## 6. Режимы работы и фазы движения

Сервопривод нельзя корректно диагностировать без учёта режима.

Один и тот же ток может быть нормальным при разгоне, но подозрительным при удержании.

Поэтому модель должна определять или использовать режимы:

- удержание;
- разгон;
- равномерное движение;
- торможение;
- останов;
- неизвестный режим.

---

### 6.1. Удержание

Признаки:

- скорость около нуля;
- положение почти не меняется;
- ток может быть небольшим;
- момент может присутствовать, если есть внешняя нагрузка.

Диагностические риски:

- высокий ток при удержании;
- рост температуры при удержании;
- микроколебания положения;
- дрожание скорости около нуля.

---

### 6.2. Разгон

Признаки:

- скорость увеличивается;
- ускорение положительное;
- ток и момент могут расти.

Диагностические риски:

- слишком высокий пиковый ток;
- слишком высокий момент;
- нестабильная DC-шина;
- повторяющиеся выбросы при каждом разгоне.

---

### 6.3. Равномерное движение

Признаки:

- скорость примерно постоянна;
- ускорение близко к нулю;
- ток и момент соответствуют нагрузке.

Диагностические риски:

- рост тока при той же скорости;
- рост момента;
- нестабильность скорости;
- вибрации;
- нестабильность питания.

---

### 6.4. Торможение

Признаки:

- скорость уменьшается;
- ускорение отрицательное;
- возможны изменения DC-шины из-за рекуперации.

Диагностические риски:

- рост напряжения DC-шины;
- слишком резкое торможение;
- превышение пикового тока;
- повторяющиеся скачки напряжения.

---

### 6.5. Останов

Признаки:

- скорость близка к нулю;
- момент и ток близки к нулю;
- привод может быть выключен или готов к работе.

Диагностические риски:

- наличие ошибки;
- высокая температура после нагрузки;
- нестабильность данных;
- зависшие значения телеметрии.

---

## 7. Health Score

Health Score — интегральная оценка состояния привода по шкале от 0 до 100.

Интерпретация:

| Health Score | Состояние             |
| -----------: | --------------------- |
|       85–100 | Норма                 |
|        70–84 | Наблюдение            |
|        50–69 | Предупреждение        |
|         0–49 | Критическое состояние |

Health Score должен уменьшаться при росте рисков.

Пример:

```text
Health Score = 100 * (1 - total_risk)
```

где `total_risk` — взвешенная сумма физических и статистических рисков.

---

## 8. Anomaly Score

Anomaly Score — оценка нетипичности поведения от 0 до 1.

Интерпретация:

| Anomaly Score | Состояние                |
| ------------: | ------------------------ |
|     0.00–0.25 | Нормальное поведение     |
|     0.25–0.50 | Небольшое отклонение     |
|     0.50–0.75 | Подозрительное поведение |
|     0.75–1.00 | Аномальный режим         |

Anomaly Score не заменяет Health Score.

Разница:

- Health Score показывает техническое состояние относительно пределов.
- Anomaly Score показывает отличие от нормального профиля.

---

## 9. Диагностические причины

Модель должна не только выдавать итоговое состояние, но и объяснять его.

Пример причин:

- повышенный RMS-ток;
- высокий пиковый ток;
- момент близок к номинальному;
- температура растёт;
- напряжение DC-шины нестабильно;
- найден ненулевой код ошибки;
- `statusword` содержит Fault;
- текущий режим отличается от нормального профиля;
- данные имеют плохое качество.

---

## 10. Рекомендации

Модель должна выдавать простые инженерные рекомендации.

Примеры:

| Причина                         | Рекомендация                                            |
| ------------------------------- | ------------------------------------------------------- |
| Высокий ток при низкой скорости | Проверить механическую нагрузку, муфту, заклинивание    |
| Рост температуры                | Проверить охлаждение, вентиляцию, длительность цикла    |
| Нестабильная DC-шина            | Проверить питание, тормозной резистор, режим торможения |
| Ненулевой код ошибки            | Проверить код ошибки по руководству привода             |
| Микроколебания                  | Проверить настройки контура, механику, крепления        |
| Потеря данных                   | Проверить связь edge/backend и буфер телеметрии         |

В первой версии рекомендации должны быть rule-based, то есть на основе правил, без LLM.

---

## 11. Главная инженерная идея

Сырая телеметрия сама по себе мало полезна.

Задача модели — выполнить преобразование:

```text
сырые параметры
    ↓
инженерные признаки
    ↓
риски
    ↓
Health Score и Anomaly Score
    ↓
состояние
    ↓
объяснение
    ↓
рекомендация
```

Итоговая модель должна помогать оператору или инженеру ответить на вопросы:

1. Всё ли нормально с приводом?
2. Есть ли ранние признаки проблемы?
3. Какой параметр вызывает риск?
4. Насколько это опасно?
5. Что нужно проверить?
