# 02_TELEMETRY_SCHEMA.md

# Схема телеметрии сервопривода

## 1. Назначение документа

Этот документ строго описывает входные данные для проекта `servo_diagnostic_model`.

Coding agent должен реализовать загрузку, валидацию и нормализацию телеметрии в соответствии с этой схемой.

Основная цель — привести любые входные данные к единому каноническому формату, с которым дальше будут работать модули:

- windowing;
- feature extraction;
- physical risk model;
- statistical anomaly model;
- health score;
- classifier;
- recommendations.

---

## 2. Общий принцип работы с данными

Входная телеметрия может поступать из:

- CSV-файла;
- SQLite-базы;
- JSON;
- backend API;
- эмулятора;
- реального edge-уровня.

В первой версии обязательно реализовать поддержку CSV.

Поддержка SQLite может быть добавлена позже, но архитектура должна позволять добавить новый loader без переписывания диагностической модели.

---

## 3. Что такое сэмпл телеметрии

Сэмпл телеметрии — это один срез состояния привода в конкретный момент времени.

Пример одной строки:

```json
{
  "ts": "2026-04-29T12:29:48.100",
  "t": 0.1,
  "device_id": "servo_1",
  "statusword": 4663,
  "mode_display": "Profile Velocity",
  "position": 123456,
  "velocity": 850.0,
  "torque": 15.0,
  "torque_Nm": 0.041,
  "current": 21.0,
  "current_A": 0.089,
  "dc_bus_voltage": 305.2,
  "drive_temp": 37.0,
  "error_code": 0
}
```

Не все поля всегда обязательны. Но для полноценной диагностики нужен минимальный набор.

---

## 4. Каноническая схема данных

Все входные данные должны быть приведены к следующей внутренней структуре.

### 4.1. Обязательные поля

| Поле             |                  Тип | Единица | Описание                   | Использование                      |
| ---------------- | -------------------: | ------- | -------------------------- | ---------------------------------- |
| `ts`             | `datetime` или `str` | —       | абсолютная временная метка | сортировка, ось времени            |
| `t`              |              `float` | s       | время от начала записи     | windowing, графики, расчёт частоты |
| `velocity`       |              `float` | RPM     | скорость вращения          | фазы движения, риск скорости       |
| `current_A`      |              `float` | A       | ток в амперах              | RMS-ток, риск нагрузки             |
| `torque_Nm`      |              `float` | Н·м     | момент                     | риск момента                       |
| `dc_bus_voltage` |              `float` | V       | напряжение DC-шины         | риск OV/UV, стабильность питания   |
| `drive_temp`     |              `float` | °C      | температура привода        | тепловой риск                      |
| `statusword`     |                `int` | —       | слово состояния привода    | Fault/Warning/operation flags      |
| `error_code`     |                `int` | —       | код ошибки                 | аварийная диагностика              |

---

### 4.2. Желательные поля

| Поле               |               Тип | Единица    | Описание                 | Использование                      |
| ------------------ | ----------------: | ---------- | ------------------------ | ---------------------------------- |
| `device_id`        |             `str` | —          | идентификатор устройства | фильтрация по приводу              |
| `mode_display`     |             `str` | —          | режим работы             | анализ режима                      |
| `position`         | `float` или `int` | increments | положение энкодера       | удержание, движение, микровибрации |
| `torque`           |           `float` | promille/% | относительный момент     | fallback для `torque_Nm`           |
| `current`          |           `float` | promille/% | относительный ток        | fallback для `current_A`           |
| `rated_current_A`  |           `float` | A          | номинальный ток          | нормирование риска                 |
| `max_current_A`    |           `float` | A          | максимальный ток         | нормирование риска                 |
| `rated_torque_Nm`  |           `float` | Н·м        | номинальный момент       | нормирование риска                 |
| `max_torque_Nm`    |           `float` | Н·м        | максимальный момент      | нормирование риска                 |
| `max_velocity_rpm` |           `float` | RPM        | максимальная скорость    | нормирование риска                 |

## 6. Правила обязательности

### 6.1. Минимальный набор для физической диагностики

Для версии 0.1 обязательно нужны:

```text
t или ts
velocity
current_A
torque_Nm
dc_bus_voltage
drive_temp
statusword
error_code
```

Если нет `torque_Nm`, но есть `torque`, модель может работать с ограниченной диагностикой момента.

Если нет `current_A`, но есть `current`, модель может работать с относительным током, но в отчёте нужно пометить, что диагностика тока ограничена.

---

### 6.2. Минимальный набор для windowing

Для оконной обработки нужно одно из полей:

```text
t
```

или

```text
ts
```

Если есть только `ts`, нужно вычислить `t` как время от начала записи.

Если есть только `t`, `ts` можно оставить как `None`.

---

### 6.3. Минимальный набор для диагностики ошибок

Нужны:

```text
statusword
error_code
```

Если `statusword` отсутствует, нужно выставить:

```python
statusword_available = False
```

Если `error_code` отсутствует, нужно выставить:

```python
error_code_available = False
```

Но лучше считать отсутствие этих полей ухудшением качества данных.

## 8. Правила предобработки

### 8.1. Сортировка

Все строки должны быть отсортированы по времени.

Приоритет сортировки:

1. `t`;
2. `ts`;
3. исходный порядок, если времени нет.

Если время отсутствует, это критическая проблема для оконной диагностики. В таком случае нужно вернуть ошибку валидации.

---

### 8.2. Вычисление `t`

Если поле `t` отсутствует, но есть `ts`, нужно вычислить:

```text
t = ts - ts_min
```

в секундах.

---

### 8.3. Преобразование чисел

Все числовые поля должны быть приведены к `float`, кроме:

- `statusword`;
- `error_code`.

Они должны быть приведены к `int`.

Если преобразование невозможно, значение считается некорректным.

---

### 8.4. Обработка пропусков

Пропуски бывают двух типов:

1. Пропущено значение параметра.
2. Пропущен участок времени.

Если пропущено значение параметра:

- не удалять строку сразу;
- пометить качество данных;
- для расчёта признаков можно использовать `nan`-safe функции;
- при большом числе пропусков повысить `data_quality_risk`.

Если пропущен участок времени:

- посчитать разрыв;
- сравнить с ожидаемым шагом дискретизации;
- повысить `data_quality_risk`;
- сохранить информацию о разрыве в признаках окна.

---

## 9. Некорректные значения

### 9.1. Температура

Некорректные значения:

- ниже -40 °C;
- выше 150 °C;
- `NaN`;
- строка вместо числа.

Действие:

- пометить как invalid;
- не использовать в физических рисках;
- повысить риск качества данных.

---

### 9.2. Напряжение DC-шины

Некорректные значения:

- отрицательное напряжение;
- ноль при работающем приводе, если остальные параметры активны;
- экстремально большое значение;
- `NaN`.

Действие:

- пометить как invalid;
- повысить риск качества данных.

---

### 9.3. Скорость

Скорость может быть отрицательной, если привод вращается в обратном направлении.

Некорректные значения:

- `NaN`;
- бесконечность;
- экстремально большое значение, намного выше физического предела.

Для риска скорости используется модуль:

```text
abs(velocity)
```

---

### 9.4. Ток

Ток может быть отрицательным в некоторых системах в зависимости от направления момента или формата данных. Для нагрузки использовать абсолютное значение или RMS.

Некорректные значения:

- `NaN`;
- бесконечность;
- экстремально большое значение без физического смысла.

---

### 9.5. Момент

Момент может быть отрицательным.

Для оценки нагрузки использовать:

```text
abs(torque_Nm)
```

или RMS.

---

## 10. Оценка частоты дискретизации

Нужно реализовать функцию:

```python
estimate_sampling_rate(samples) -> float
```

Логика:

1. Взять отсортированный массив `t`.
2. Посчитать разности между соседними значениями.
3. Взять медианный шаг.
4. Частота:

```text
sampling_rate = 1 / median_dt
```

Если `median_dt <= 0`, вернуть ошибку.

---

## 11. Формат окна телеметрии

Окно телеметрии — это набор сэмплов в диапазоне:

```text
window_start <= t < window_end
```

Рекомендуемая первая настройка:

```text
window_seconds = 5
window_step_seconds = 1
```

При частоте 10 Гц в окне будет примерно 50 точек.

Окно должно содержать достаточно данных. Если точек слишком мало, окно нужно пометить как низкокачественное.

---

## 12. Data Quality

Для каждого окна нужно рассчитывать качество данных.

Признаки качества:

| Признак                   | Описание                      |
| ------------------------- | ----------------------------- |
| `missing_ratio`           | доля пропущенных значений     |
| `invalid_ratio`           | доля некорректных значений    |
| `time_gap_count`          | количество временных разрывов |
| `sampling_rate_estimated` | оценочная частота             |
| `is_too_short`            | слишком мало точек в окне     |
| `flatline_flags`          | зависшие значения параметров  |

---

## 13. Flatline detection

Flatline — ситуация, когда параметр долго не меняется.

Это может быть нормой для некоторых параметров, например температуры, но подозрительно для других.

Пример:

- `velocity` = 0 всё окно при останове — нормально;
- `dc_bus_voltage` абсолютно одинаковый без шума долгое время — возможно, данные эмулятора или зависшее значение;
- `current_A` абсолютно одинаковый при движении — возможно, проблема данных.

В первой версии flatline использовать только как признак качества данных, не как прямую аварию.

---

## 14. Нормализация паспортных пределов

Паспортные пределы могут приходить:

1. В каждой строке телеметрии.
2. В отдельном конфигурационном файле.
3. В метаданных устройства.

Приоритет:

1. Конфиг `limits.json`.
2. Поля в телеметрии.
3. Значения по умолчанию.
4. Если предела нет — соответствующий риск считается недоступным.

## 15. Пример канонического сэмпла Python

В коде желательно использовать `dataclass`.

Пример:

```python
from dataclasses import dataclass
from datetime import datetime
from typing import Optional

@dataclass
class TelemetrySample:
    t: float
    ts: Optional[datetime]
    device_id: Optional[str]
    statusword: Optional[int]
    mode_display: Optional[str]
    position: Optional[float]
    velocity: Optional[float]
    torque: Optional[float]
    torque_Nm: Optional[float]
    current: Optional[float]
    current_A: Optional[float]
    dc_bus_voltage: Optional[float]
    drive_temp: Optional[float]
    error_code: Optional[int]
```

## 16. Ошибки валидации

Нужно различать:

1. Critical validation error.
2. Warning validation issue.

### 16.1. Critical validation error

Примеры:

- нет времени;
- нет ни одного параметра для диагностики;
- файл пустой;
- все строки некорректны;
- невозможно отсортировать данные.

В этом случае диагностика не должна выполняться.

---

### 16.2. Warning validation issue

Примеры:

- отсутствует `position`;
- отсутствует `mode_display`;
- отсутствует `torque_Nm`, но есть `torque`;
- есть отдельные пропуски;
- есть незначительные временные разрывы.

В этом случае диагностика может выполняться, но качество данных должно влиять на результат.

---

## 17. Ожидаемый выход после предобработки

После загрузки и предобработки должен быть получен объект:

```python
TelemetryDataset
```

Пример полей:

```python
@dataclass
class TelemetryDataset:
    samples: list[TelemetrySample]
    columns_available: dict[str, bool]
    validation_errors: list[str]
    validation_warnings: list[str]
    sampling_rate_hz: float | None
    duration_s: float | None
    device_id: str | None
```

## 18. Acceptance criteria

Модуль работы с телеметрией считается готовым, если:

1. CSV загружается.
2. Алиасы полей приводятся к каноническим именам.
3. Время приводится к `t` в секундах.
4. Данные сортируются.
5. Числовые поля приводятся к числам.
6. Некорректные значения не ломают программу.
7. Есть список ошибок и предупреждений валидации.
8. Оценивается частота дискретизации.
9. Можно получить список сэмплов.
10. Можно передать эти сэмплы в windowing.
